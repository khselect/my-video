# motion-video — 코드 모션그래픽 제작

Claude 는 픽셀을 그리지 않는다. 좌표·숫자·타이밍으로 **움직임의 설계도(코드)** 를 쓰고 렌더한다.
그래서 결과의 품질은 거의 전부 **지시의 구체성**(이징·카메라·타이밍·리듬·색·움직이는 중 가독성)과 **검수**에서 나온다.
기본값으로 만들면 "깔끔하지만 슬라이드를 넘기는 듯한" 영상이 된다 — 이 스킬의 단계는 그걸 막기 위한 것이다.

## 0. 먼저 볼 것

- **my-video 저장소 안이면** (`studio/app.py` 가 있다): 사용자는 Lecture Studio(`python3 studio/app.py`, 7단계 승인)를 쓴다. 같은 일을 Studio 가 하므로 저장소의 `tools/`·`CLAUDE.md`·`WORKFLOW.md` 를 따르고, 이 스킬의 `scripts/` 대신 `tools/` 의 같은 이름 도구를 쓴다.
- **그 밖의 폴더**: 이 스킬의 `scripts/` 를 쓴다. 필요: ffmpeg/ffprobe, Python 3.10+ + numpy, Node 22+ (HyperFrames). 렌더 엔진은 HyperFrames(HTML) 기본, React 프로젝트면 Remotion. 레이어별로 직접 고칠 일이 있으면 처음부터 이 둘 중 하나로 만든다 — 아니면 요소 하나 고칠 때마다 대화해야 한다.
- 유료 생성(이미지·영상·음성 MCP)은 **잔액 확인 → 견적 → 사용자 확인** 뒤에만. 계획에 없는 유료 호출은 하지 않는다.

## 1. 경로 고르기 — 코드 vs 영상 생성 모델

| 영상의 성격 | 고를 것 | 이유 |
|---|---|---|
| 글자가 많다 (키네틱 타이포, 설명, 데이터, UI) · 한글 | **코드** | 글자가 깨지지 않고 수정이 쉽다. 영상 모델은 한글이 뭉개진다 |
| 규칙으로 정의되는 스타일 (ASCII, 픽셀, 한 줄 드로잉, 리소그래프, 잉크 번짐) | **코드** (한 줄 프롬프트로도 잘 됨) | 과정이 곧 규칙 |
| 질감·빛이 중요한 일러스트 (찢은 종이, 수채, 사진) + 정교한 움직임 | **이미지 에셋 + 코드** (5절) | 이미지가 질감, 코드가 움직임·전환 |
| 사실적 영상, 캐릭터 연기, 매우 복잡한 움직임, 빠른 시안 | **영상 생성 모델** | 코드로는 오래 걸리고(15초 2시간+) 어색하다 |

섞어도 된다: 핵심 장면 하나만 영상 모델, 나머지는 코드. 경로를 정하면 사용자에게 한 줄로 이유를 말한다.

## 2. 한 번에 묻기

모호한 것만 **한 메시지로** 묻고, 나머지는 기본값으로 간다: 주제·대본(없으면 리서치할 대상), 길이(기본 15~60초), 화면비(1920×1080), 나레이션(있음/없음/내 녹음), 음악(파일/없음), 레퍼런스(영상 파일·링크·스크린샷), **스토리보드 먼저 볼지**(오래 걸리거나 유료면 권장).
콘텐츠를 비워 두면 주제와 무관한 영상이 나온다 — 대본이 없으면 웹에서 대상을 리서치해 채운다.

## 3. 분석 — 측정 먼저, 추정 금지

레퍼런스 영상 파일이 있으면 숫자로 잰다 (YouTube 링크는 파일로 받은 뒤):

```bash
python3 <skill>/scripts/ref_measure.py measure ref.mp4 --range 0:00-5:00 --out ref.measure
```

→ `spec.md`(전환 시각·방식, 실효 fps·홀드 패턴, 움직임 양, 그레인, 팔레트), `contact.jpg`, `cuts.jpg`. 두 이미지는 Read 로 본다.
숫자로 못 재는 것(카메라 방향, 이징 곡선, 질감, 테두리)은 눈으로 보고 **"(추정)"** 으로 적는다. 측정과 눈이 다르면 측정을 따르고 차이를 적는다.
레퍼런스가 스크린샷뿐이면 전부 "(추정)". 판단할 근거가 없으면 "근거 부족".

음악이 있으면: `python3 <skill>/scripts/beats.py analyze music.mp3 --out beats.json` (BPM·박·강박·악센트. 템포가 두 배/절반으로 잡히면 `--bpm-hint`).

## 4. 계획 — 효과 사양표 + 스토리보드, 그리고 멈춤

`storyboard.md` 를 쓰고 **사용자 승인 전에는 제작(파일 생성·유료 호출)을 시작하지 않는다.** 크게 틀린 방향을 렌더 뒤에 고치는 비용이 가장 크다.

1. **효과 사양표** — 효과마다 한 줄: `효과 | 근거(측정값·프레임/시각) | 구현(GSAP·CSS) | 파라미터 초기값`.
   예: `2프레임 홀드 반복 | 실효 12fps, 유지 분포 2s:93 | steps / 1/12초 양자화 | ANIM_FPS=12`
2. **이 영상다움** 3~5개 (우선순위).
3. **장면표** — 장면 | 시간 | 화면 구성 | 카메라(움직임·이징·길이) | 등장 타이밍 | 전환 → 다음 | 에셋. 나레이션이 있으면 시간은 나레이션 길이가 정한다(먼저 나레이션, 영상은 그 길이에).
4. **관통 요소와 전환 문법** ([references/motion-rules.md](references/motion-rules.md) 3절).
5. **에셋 계획** — 그림마다 용도, 배경과 묶을지 투명 PNG 로 분리할지, 생성 프롬프트 초안, 모델·장수·예상 크레딧.
6. **합격 조건** — 렌더를 같은 측정 코드로 재서 볼 값(±20%): 분당 전환, 실효 fps, 움직임 양, 그레인 유무, 대표 HEX. 나레이션 길이 때문에 달라질 값은 그렇다고 적는다.
7. **확신이 낮은 부분** 2~3개 — 사용자에게 물을 것.

## 5. 제작

- 장면마다 [references/motion-rules.md](references/motion-rules.md) 를 지킨다: 움직임마다 이징(linear 금지), 장면마다 카메라 1개·영상 전체 4종 이상, 관통 요소 1개, 전환 중 빈 화면 금지, 글자 유지 (글자 수÷5+1.5)초.
- 사양표 파라미터는 **코드 한곳에 이름 붙인 상수**로 (`const FX = { ANIM_FPS: 12, GRAIN_OPACITY: 0.04, … }`). 검수 후 조정이 숫자 한 줄이 된다.
- 스톱모션·픽셀 룩도 **카메라는 매 프레임 부드럽게**, 그림만 계단식.
- 음악이 있으면 박에 맞춘다. 나레이션 영상: 장면 경계는 그대로, 장면 안 등장·강조·전환 시작만 ±0.3초 안의 박으로(강조는 강박·악센트). 나레이션 없는 영상: 길이 = 음원, 모든 컷을 박에, 단 매 박마다 컷하지는 않는다.
- **이미지 + 코드** (질감이 필요할 때): 같은 기준 이미지·같은 외형 문장·seed 로 인물·질감 통일, 분리할 피사체는 단색 배경으로 생성, 오려 붙이는 조각은 불규칙한 가장자리 + 옅은 그림자(일자로 잘린 가장자리 금지), 화면 가득 그림은 10% overscan, 그림 안에 글자 넣지 않기. 이미지는 질감·빛, 코드는 움직임·전환·카메라·글자.
- 키네틱 타이포가 첫 실험으로 좋다 — 형태를 유지해야 할 대상이 적어 타이밍·이징을 보기 쉽다.

## 6. 검수 — 같은 측정 코드로

렌더 뒤 사람이 보기 전에 기계가 잡을 것을 잡는다:

```bash
python3 <skill>/scripts/qa_render.py out.mp4 --normalize          # 빈 화면·멈춤·음량(−14 LUFS 맞춤)·(--lecture 있으면 읽기 시간)
python3 <skill>/scripts/ref_measure.py compare ref.measure out.mp4  # 레퍼런스 대조표 ±20%
python3 <skill>/scripts/beats.py check beats.json out.mp4           # 전환이 박 위인지 (ms)
python3 <skill>/scripts/stt_check.py <project> --engine auto        # 나레이션 오독 (whisper, build/audio 구조일 때)
```

- 결함(빈 화면·멈춤·전환 끊김·형태 오류)은 **한 번의 수정 라운드**에 모두 고치고 다시 렌더·검사한다.
- 대조표의 ❌ 는 원인을 적고 상수를 조정한다. 움직임 양은 정규화한 그래프가 아니라 절대값으로 비교한다.
- 우리 영상이 레퍼런스와 **달라야 할 이유**가 있는 값(나레이션 때문에 긴 샷 등)은 그대로 두고 이유를 적는다.

## 7. 납품

MP4(음악·효과음 포함), `storyboard.md`(효과 사양표·최종 상수와 코드 위치), 검사 결과(qa·대조표·박자), 생성한 에셋과 프롬프트(모델·설정·크레딧), 남은 차이. 걸린 시간도 적는다.
마음에 드는 결과가 나오면 사용자에게 제안한다: "이 스타일을 스킬로 저장해 다음 주제에도 쓰기" — 스타일 불변 요소(색·타이포·모션 문법·전환·관통 요소 규칙)만 적고, 이야기·장면은 빼서.

## 저작권·안전

레퍼런스는 문법만 배운다: 캐릭터·로고·구체적 장면·문구·멜로디·폰트를 가져오지 않는다. 레퍼런스 프레임은 저장소에 커밋하지 않는다(측정 수치만). 생성 이미지가 들어간 영상은 게시 때 AI 생성 표시를 권한다. 내 목소리 복제는 본인 동의가 있을 때만.
