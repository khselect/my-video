# 모션 연출 규칙 (모든 스타일 공통)

장면을 만들기 전에 이 문서를 읽는다. 목적은 하나다. 기본값으로 만들면 생기는 **"깔끔하지만 슬라이드를 넘기는 듯한 영상"** 을 막는 것.
근거: 코드 모션그래픽 실험 영상 분석([prompts.md](prompts.md)) — 이징·카메라·타이밍을 숫자로 지정할수록 결과가 좋아지고, 첫 결과의 공통 약점은 "카메라가 거의 안 움직이고 장면을 잇는 요소가 없다"였다.

스킬(SKILL.md)이 고정한 안무·카메라·전환이 있으면 **스킬이 우선**한다. 이 규칙은 스킬이 정하지 않은 부분을 채운다.
숫자는 시작값이다. 렌더 후 검사(`scripts/qa_render.py`)와 레퍼런스 측정(`scripts/ref_measure.py`) 수치로 조정한다.

## 1. 이징 — 움직임마다 곡선을 고른다 (GSAP 이름)

| 움직임 | 곡선 | 길이 |
|---|---|---|
| 등장 (글자·카드) | `power3.out` / `expo.out` | 0.4~0.6초 |
| 퇴장 | `power2.in` | 0.25~0.35초 (등장보다 짧게) |
| 화면 안에서 위치·크기 이동 | `power2.inOut` / `expo.inOut` | 0.6~1.0초 |
| 강조 팝 | `back.out(1.8~2.5)` | 0.3~0.5초 |
| 떨어져 쌓임 | `bounce.out` | 0.5~0.7초 |
| 카메라 이동 | `sine.inOut` / `power1.inOut` | 장면 길이의 40~100% |
| 스톱모션·픽셀·종이 질감 스타일 | `steps(n)` 또는 12fps 계단 | — (카메라는 계단 없이 부드럽게) |

- `linear` 는 카운트업·회전 루프·진행 막대에만. 사람이 보는 이동에는 쓰지 않는다.
- **같은 화면의 요소는 stagger 0.06~0.12초**로 차례로 들어온다. 한꺼번에 뜨지 않는다.
- 큰 이동 뒤에는 0.05~0.1초 늦게 따라오는 작은 움직임(follow-through: 그림자, 밑줄, 숫자)이 하나 있으면 살아 보인다.
- 마이크로 애니메이션: 숫자는 카운트업, 강조 단어는 색·밑줄이 그려지고, 클릭·선택을 말할 때는 눌림(scale 0.96→1) 을 준다.

## 2. 카메라 — 2D 에도 카메라가 있다

- 장면마다 **카메라 움직임 1개**: 밀기(push-in, scale 1→1.06~1.15), 당기기(pull-out), 패닝(x ±3~6%), 틸트, 초점 이동(배경 blur 0→4px), 시차(패럴랙스: 배경 0.5배·전경 1배 속도).
- 영상 전체에서 **서로 다른 카메라 움직임 4종 이상**. 연속 두 장면이 같은 움직임이 되지 않게.
- 중요한 말(핵심 단어·숫자·결론)을 하는 순간 **그 요소로 줌인**(0.6~0.9초, `power2.inOut`), 다음 요소로 넘어갈 때 줌아웃.
- 구현: 장면 내용을 `<div id="<id>-cam">` 하나로 감싸고 그 div 만 움직인다. 글자 크기·위치를 직접 키우지 않는다.
- 줌·패닝을 쓰는 그림·배경은 **화면보다 10% 이상 크게**(overscan) 깔아 가장자리가 드러나지 않게 한다.
- 핵심 순간의 피사체는 화면 높이의 1/3 이상. 가장자리에 붙이지 않는다(안전영역 90%).

## 3. 장면 연결 — 슬라이드처럼 넘기지 않는다

- **관통 요소 1개**: 영상 전체를 잇는 요소를 하나 정한다(강조색 점·선, 진행 막대, 주인공 아이콘, 종이 조각 등). 루트 `index.html` 의 위쪽 트랙(전체 길이)에 두고, 장면이 바뀔 때 다음 장면의 핵심 위치로 이동·변형한다.
- **매치 컷**: 앞 장면 마지막 요소의 위치·모양·색이 다음 장면 첫 요소로 이어진다(점이 원이 되고, 막대가 축이 되는 식). 전환 전후 피사체의 위치·이동 방향·속도를 이어 시선이 끊기지 않게 한다.
- 전환은 기본 페이드 대신 **매체 안에서**: 와이프, 마스크 리빌, 줌 스루(관통 요소로 들어가며 다음 장면), 밀어내기. 한 영상에서 전환 문법은 2~3종으로 일관되게.
- **빈 프레임 금지**: 전환 중에도 화면에 무언가(관통 요소·배경 질감)가 보인다. 장면 끝 opacity 0 정리는 다음 장면 등장과 **겹치게**(0.2~0.35초) 한다. 0.1초 이상 아무것도 없는 화면을 만들지 않는다.
- 리듬: 빠른 장면과 느린 장면을 교차하고, 숨 쉬는 구간(1.5초 이상 거의 정지)을 영상에 한 번 둔다. 모든 장면이 같은 속도면 실패.

## 4. 글자 가독성 — 읽을 시간을 준다

- 움직이는 중에도 글자는 또렷해야 한다: 글자 자체에 blur·회전·과한 skew 를 0.3초 넘게 걸지 않는다. 이동 중인 글자는 28px 이상.
- 등장이 끝난 뒤 유지 시간(한국어, 시작값): **글자 수 ÷ 5 + 1.5초**. 예: 15자 → 4.5초. 나레이션이 같은 내용을 말하는 중이면 그 발화가 끝날 때까지는 유지.
- 자막은 최소 1.8초, 발화 길이 + 0.6초 이상. 피사체·핵심 그림을 가리지 않는다.
- 타이틀 카드는 4초 이상.
- 빠르게 하고 싶으면 화면의 글자 수를 줄인다. 다 읽기 전에 컷하지 않는다.

## 5. 이미지 에셋 (그림을 생성하는 스타일)

- 오려 붙이는 피사체(스티커·종이 조각)는 **배경이 분리된 이미지**로 만들고, 가장자리는 찢거나 가위로 자른 **불규칙한 테두리 + 옅은 그림자**. 직사각형 그림을 그대로 잘라 붙이지 않는다(일자로 잘린 가장자리 금지).
- 화면 가득 까는 그림은 overscan(2절) 을 지키고, 그림 안의 주인공이 글자 판에 가리지 않는 구도로 요청한다.
- 같은 인물·질감은 같은 외형 문장 + 같은 seed(또는 같은 기준 이미지)로 통일한다.
- 그림이 맡는 것은 질감·빛·세부 묘사, 코드가 맡는 것은 움직임·전환·카메라·글자. 그림 안에 글자를 넣지 않는다(`no text, no letters`).

## 6. 끝나기 전에 확인

- [ ] 장면마다 이징이 지정됐다 (`linear`·기본값 이동 없음)
- [ ] 카메라 움직임 4종 이상, 연속 장면 중복 없음
- [ ] 관통 요소 1개가 처음부터 끝까지 이어진다
- [ ] 전환 구간에 빈 화면이 없다 (`qa_render.py` 빈 화면 검사 + 전환 직전·직후 프레임 확인)
- [ ] 글자 유지 시간 규칙을 지켰다
- [ ] 결과 보고에 "관통 요소 / 카메라 움직임 목록 / 전환 문법"을 한 줄씩 적는다
