### A-2. 이미지 에셋 + 코드 4단계 프롬프트 (요약)

**입력**: 레퍼런스 영상(링크/파일), 새 주제, 길이, 해상도, *가져올 것*(예: 끊기는 스톱모션 리듬, 종이 질감·그림자), *가져오지 않을 것*(예: 로고, 브랜드 문구). 이미지 모델 기본값은 GPT Image 계열.

**공통 원칙**
- **측정 먼저, 추정 금지.** 판단 근거는 코드로 측정한 수치와 프레임 번호. 눈으로 본 항목은 "추정" 표시.
- 레퍼런스는 처음부터 끝까지 훑고, **마지막 2초 엔딩**을 따로 확인.
- 측정 코드는 저장해 두고 검수 때 결과물에 그대로 다시 쓴다.

**1단계 — 분석과 플랜 (여기서 멈추고 승인)**
1. **레퍼런스 스펙 시트** — 주요 장면과 전환 전후 프레임을 실제로 보고 측정:
   - 연출: 장면별 시간표, 피사체 위치·크기, 카메라 이동 방향·속도, 전환 방식. 전환 위치 = **연속 프레임 차분이 급증하는 지점**, 방식은 컷/줌/와이프/디졸브/플래시.
   - 움직임 문법: **실제 애니메이션 fps = 프레임 차분이 0 이 되는 홀드 패턴**(1s/2s/3s), 보간(이징/계단/반동), 모션 블러, 등장·퇴장 프레임 수, 포즈 교체 방식, **구간별 움직임 양 = 저해상도(예 96×54) 프레임 차분 평균의 절대값 표**.
   - 물성: 레이어 깊이(그림자·시차), 질감, 테두리, 색(대표 HEX, 채도·명도 평균, 흰색 비율), 그레인이 매 프레임 바뀌는지, 정지 구간의 미세 움직임(보일링·핸드헬드·플리커), 하프톤·비네팅·블러·색수차.
   - 사운드: BPM·장르, 강박 위치, 효과음 지점.
   - "이 영상다움"을 만드는 특징 3~5개, 우선순위.
2. **효과 사양표** — 효과마다 `근거(측정값·프레임 번호) → 구현 방법 → 코드 파라미터 초기값` 한 줄. 예: 홀드 2·3프레임 반복 → 12fps 양자화 → `ANIM_FPS=12`.
3. **장면 대응표** — 연출 구조는 유지, 소재만 새 주제로: `레퍼런스 장면·시간 → 새 소재 → 구현 방식`.
4. **에셋 목록** — 용도, 배경과 묶을지/투명 PNG 로 분리할지, 기준 이미지, 필요한 각도·포즈, 모델 설정·프롬프트 초안.
   - 같은 기준 이미지를 참조(image2image)해 캐릭터·질감 통일. 회전·자세 변화에 필요한 것만 추가 생성.
   - 분리할 피사체는 **이미 단색 배경으로 분리된 이미지**를 참조해 생성.
   - 생성 건수를 모델·해상도별로 합산. 모델 설정은 실시간 스키마로 확인.
5. **장면별 구현 계획**(카메라·등장·반동·가림·전환·타이밍), 사운드 계획, **검수 기준(구간별 움직임 양 허용 오차 ±20%)**.
6. 레퍼런스 핵심 장면 캡처와 함께 보여 주고 **생성을 시작하지 말고 멈춤**.

**2단계 — 제작 (승인 후 최종까지)**
7. 승인된 모델로만 에셋 생성, 불필요한 변형·중복 렌더 줄이기.
8. 에셋을 레이어로 합성, 사양표 파라미터를 **코드 한곳에 이름 붙여 모음**. 전환 전후 피사체 위치·방향·속도를 이어 시선이 끊기지 않게. 장면 전체 확대가 아니라 요소별 역할에 맞는 움직임.
9. 검수 두 가지:
   - 결함: 형태 오류, 위치 튐, 전환 끊김, 빈 화면 → 전환 구간 프레임 시트 + 자동 검사.
   - 닮음: 1단계 측정 코드를 결과물에 → 대조표. 움직임 양은 **절대값**으로 비교, ±20% 초과·우선순위 특징은 원인 적고 재렌더. 장면별 레퍼런스/결과 프레임 나란히.

**납품물**: 음악·효과음 포함 MP4, 이미지 에셋, 생성 프롬프트(모델·설정), 합성 코드, 스펙 시트·효과 사양표(최종 값과 코드 위치)·측정 대조표, 남은 차이.

## B. lemo-opuscar (lemomo-ai, MIT / 데모 CC BY 4.0)

코드만으로 영화형 단편을 만드는 Claude Code 플러그인. 스타일 66개(`styles/<slug>/STYLE.md` + 데모), 영상 생성 모델 없음.
설치: `claude plugin marketplace add lemomo-ai/lemo-opuscar` → `claude plugin install lemo-opuscar@lemolab`. 요구: Node 20+, **ffmpeg 7+**, Python 3.11+. 1편 30~60분.

### 구조
- `DIRECTOR.md`(연출) · `TECHNIQUE.md`(제작) · `STYLE.md`(스타일 불변 요소) 세 문서를 에이전트가 읽음.
- 사용자 스타일은 `~/lemo-my-styles/` 에 저장(라이브러리 업데이트와 분리): `STYLE.md`(불변 요소만) · `CHANGES.md`(결정 기록) · `DEMO.md` · 승인된 스타일 프레임 · 15~30초 테스트 영상.
- 스타일 만들기: 질문은 한 번에 하나(추천안 먼저, 최대 약 10개) → 요약 승인 → 스타일 프레임 1장 승인 → 데모 → 저장.

### 이 저장소에 가져올 만한 규칙 (DIRECTOR.md)
- 평가 순서: **사운드 → 리듬 → 카메라 → 연출**. 예쁜 프레임은 출발점일 뿐.
- **벤치마크 먼저**: 스타일·주제에 맞는 참고작 1~2개, "배울 것 / 가져오지 않을 것"을 적는다.
- 이야기: 대상 하나·목표 하나·전환 하나, **첫 3초 훅**, 시작을 되받는 엔딩, 매체 고유의 동작(native move) 하나를 감정 정점에.
- `TREATMENT.md` 를 먼저: 후보 구조 3개와 선택 이유, 로그라인, 샷 리스트(프레이밍·앵글·카메라·길이·이유), 초 단위 비트 시트, **큐 맵**(템포·마디·컷이 떨어지는 박), 사운드 디자인 표, 자막·타이틀 디자인.
- 스토리보드는 요청 시만: 실제 그리기 코드로 6~9컷 시트 → 승인 대기.
- 사운드: 보이는 동작마다 소리, 3층(앰비언스·폴리·음악), **실제 정적 2번 이상**, 사운드로 전환(J/L컷) 2번 이상, 뻔한 피아노+현악 금지.
- 리듬: 큐 맵을 먼저, 그림이 그리드에 고정. 빠름·느림 교차, 가속/감속 1번, 숨 쉬는 구간 1번. 비트마다 컷하지 않음.
- **읽기 시간**: 자막 최소 1.8초(발화 + 0.6초 이상), 텍스트 등장 후 유지 ≈ 글자수÷15+1.5초(영어) / 글자수÷4.5+1.5초(중국어), 타이틀 4초 이상.
- 카메라: **서로 다른 카메라 무브 4개 이상**, 시그니처 샷 1개, 전환은 매체 안에서(페이지 넘김·잉크 번짐), 기본 페이드·하드컷 지양, 핵심 순간 피사체 ≥ 화면 높이 1/3.
- 자주 본 실패: 피사체가 작거나 가장자리, 같은 색 위에 같은 색, 자막이 피사체를 가림, 너무 빠른 개그, **전환의 빈 프레임**, 카메라 이동 후 효과가 피사체를 놓침.
- 납품 전: 수정 1라운드, 데모와 6개 항목 중 4개 이상 달라야 함, 음성은 STT 로 되읽어 확인, −14 LUFS, 검은 프레임 없음.

### 가져올 만한 기술 (TECHNIQUE.md)
- **화면 = 시간의 함수** `window.render(t)` (결정적: `Date.now()`·시드 없는 `Math.random()` 금지) → 어떤 프레임이든 단독·병렬 렌더.
- **하나의 타임라인**(`timeline.js`: 구간·BPM·박·히트)이 그림·음악·자막·검사를 모두 구동. `cuecheck` 로 시각 히트와 음악 큐 차이 0ms 목표.
- 스톱모션·픽셀·셀 룩은 12fps 계단식으로 움직이되 **카메라·조명은 매 프레임 부드럽게**.
- 그레인은 페이지가 아니라 ffmpeg 에서(압축·속도).
- 음성: 줄마다 TTS → **faster-whisper 로 되읽어 대조** → 단어 타이밍. 숫자는 TTS 에선 풀어 쓰고 자막엔 숫자로. 음성은 음악보다 약 10dB 위.
- 믹스: `mux.sh` 2패스 loudnorm −14 LUFS + true-peak 제한. 검수: 1~2초 간격 컨택트 시트, 핵심 동작 0.2초 스트립, `ebur128`·`blackdetect`.
- `readcheck.mjs`: `window.TEXTS(t)` 로 화면 글자가 읽을 만큼 오래 있는지 자동 검사.
